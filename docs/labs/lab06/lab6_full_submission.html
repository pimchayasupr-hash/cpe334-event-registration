    Appendix A — Sprint 1 Contract Acceptance Criteria (Verbatim Excerpts)

    F-01: Authentication & Session Contract (f-01-auth-session.md)

    3. Acceptance Criteria (AC)

    AC IDCriterion (Observable Expected Outcome)Linked Req
    AC-F01-01Given a seeded user (ORGANIZER or PARTICIPANT), when POST /api/auth/login is called with valid email and password, then the server responds 200 OK, sets an httpOnly sid cookie (crypto.randomBytes(32).toString('hex')), creates a Session record in PostgreSQL with an 8-hour expiry, and returns { user: { id, email, name, role } } without passwordHash.FR-01, NFR-01, NFR-02
    AC-F01-02Given an invalid password or unknown email, when POST /api/auth/login is called, then the server responds 401 Unauthorized, sets no session cookie, and creates no Session row in PostgreSQL.FR-01, NFR-02
    AC-F01-03Given a valid active sid cookie, when GET /api/auth/me is called, then the server responds 200 OK with the authenticated user's { id, email, name, role }.FR-01, NFR-02
    AC-F01-04Given no sid cookie or an unrecognized token, when GET /api/auth/me is called, then the server responds 401 Unauthorized without returning user data.FR-01, NFR-02
    AC-F01-05Given a logged-in session, when POST /api/auth/logout is called, then the Session row is removed from PostgreSQL, the cookie is cleared, and a subsequent GET /api/auth/me using the old cookie returns 401 Unauthorized.FR-01, NFR-02, NFR-04
    AC-F01-06Given a Session row in PostgreSQL whose expiresAt timestamp is in the past, when GET /api/auth/me is called with that session's cookie, then the server responds 401 Unauthorized.NFR-02
    AC-F01-07Given a login request with an empty/missing email or empty/missing password, when POST /api/auth/login is called, then the server responds 400 Bad Request with a validation error message and creates no Session row in PostgreSQL.FR-01

    F-02: Event Management Contract (f-02-event-management.md)

    3. Acceptance Criteria (AC)

    AC IDCriterion (Observable Expected Outcome)Linked Req
    AC-F02-01Given an authenticated ORGANIZER, when POST /api/events is called with valid fields and 1 <= capacity <= 500, then the event is stored in PostgreSQL with status = 'DRAFT' and organizerId = currentUser.id, returning 201 Created.FR-02, BR-01, AD-03
    AC-F02-02Given an authenticated ORGANIZER, when POST /api/events is called with capacity < 1 (e.g., 0, -1), capacity > 500 (e.g., 501), or endAt <= startAt, then the request is rejected with 400 Bad Request and no event is saved.BR-01, BR-02, AD-02
    AC-F02-03Given a DRAFT event owned by the authenticated ORGANIZER with startAt > now, when POST /api/events/:id/publish is called, then status updates to 'PUBLISHED' in PostgreSQL and the event appears in GET /api/events.FR-02, FR-03, BR-02
    AC-F02-04Given a DRAFT event whose startAt is in the past (startAt <= now), when POST /api/events/:id/publish is called, then the server responds 400 Bad Request and the event remains 'DRAFT'.BR-02, AD-03
    AC-F02-05Given a DRAFT event, when a PARTICIPANT calls GET /api/events or GET /api/events/:id, then the DRAFT event is excluded from the list and GET /api/events/:id returns 404 Not Found.FR-03, BR-03
    AC-F02-06Given an event with k active registrations, when the owning ORGANIZER calls PATCH /api/events/:id/capacity with newCapacity < k, then the server responds 409 Conflict and capacity remains unchanged; when k <= newCapacity <= 500, capacity updates and returns 200 OK.FR-02, BR-01, AD-04
